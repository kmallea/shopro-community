# Using ShoPro with OBS

ShoPro works with OBS in two different ways:

| OBS feature | ShoPro purpose | Visible to the audience? |
| --- | --- | --- |
| **Custom Browser Dock** | Operate the rundown from inside OBS | No |
| **Browser Source** | Display tickers, topics, rundowns, and themed overlays | Yes |

The dock is your private production control panel. Browser sources are graphic layers placed in OBS scenes. Most productions use one ShoPro dock and one or more ShoPro browser sources.

## Add the ShoPro control dock

1. Open OBS.
2. From the top menu, select **Docks > Custom Browser Docks**.
3. Enter a dock name such as `ShoPro Control`.
4. Enter `https://shopro.live/obs` as the URL.
5. Select **Apply**, then **Close**.
6. Sign in inside the new dock if prompted.
7. Leave **Remember me** selected on a trusted production computer.
8. Open the show you intend to operate.
9. Drag and resize the dock, or attach it to your preferred OBS layout.

The `/obs` address is designed for an OBS Custom Browser Dock. It removes unnecessary page chrome and does not automatically display the ShoPro onboarding tour.

### Sign-in behavior

The OBS dock has its own browser storage. Signing in to ShoPro in Chrome, Edge, Firefox, or Safari does not automatically sign you in inside OBS.

On a trusted production computer, **Remember me** allows the dock to renew your session for up to 90 days. You may need to sign in again after clearing the OBS browser cache, changing computers or OBS profiles, signing out, or reaching the end of the remembered session.

Do not use remembered login on a public or untrusted computer. Sign out after the production when OBS is shared with people who should not have access to your ShoPro account.

## Prepare a show in the dock

ShoPro has three operating states:

- **Edit Mode** changes the planned rundown.
- **Test Mode** rehearses the show without changing its real timing, temporary topics, or highlights.
- **Show Mode** operates the real production.

Use Test Mode before going live to verify segment transitions, graphics, shared views, and operator responsibilities. Exit Test Mode when the rehearsal is complete.

ShoPro prevents Test Mode from being entered while the real show is live. If you return to Edit Mode during a live show, the **Test** button is hidden and **Rejoin Show** returns you to the live controls. During a running test, **Rejoin Test** returns you to that rehearsal.

## Add a ShoPro graphic as a browser source

Browser sources do not use the `/obs` dock URL. Each graphic has its own source URL generated by ShoPro.

1. Open **Sources** in ShoPro.
2. Create or select the ticker, topic graphic, rundown, overlay, or themed overlay you want to display.
3. Copy its complete browser-source URL.
4. In OBS, select the scene that should contain the graphic.
5. In the **Sources** panel, select **+**, then **Browser**.
6. Give the source a clear name, such as `ShoPro Lower Third`.
7. Paste the copied URL into the **URL** field.
8. Set the width and height to match your OBS canvas or graphic design.
9. Position, scale, and crop the source as needed.
10. Trigger a test update from ShoPro and confirm it appears in OBS.

Repeat these steps for each graphic the production needs.

### Recommended browser-source settings

- Leave **Shutdown source when not visible** off when the graphic must remain connected and update while hidden.
- Use **Refresh cache of current page** when diagnosing a blank or stale source.
- Keep reusable graphics in a dedicated OBS scene and add that scene to other scenes as needed.
- Match full-canvas graphics to the OBS base canvas resolution.
- Test long titles, ticker text, and multiple rundown items at the final output resolution.
- Verify transparency, safe margins, and stacking order before the production.

## Rehearse the complete OBS workflow

1. Open the correct show in the ShoPro dock.
2. Enter Test Mode and start the test run.
3. Advance through several segments.
4. Confirm each ShoPro browser source updates.
5. Test overlay visibility and any scene changes used by the production.
6. Add a temporary live topic and a test highlight if those features will be used.
7. Verify shared Producer, Host, Guest Host, and Audience views when applicable.
8. Exit Test Mode.
9. Return OBS and ShoPro to the intended opening state.

Test Mode protects the real ShoPro show record, but it does not replace checking the complete broadcast chain. Also verify audio routing, recording, streaming-platform settings, guest connectivity, and OBS output.

## Run the live show

1. Confirm Test Mode has been exited.
2. Verify the correct OBS scene and ShoPro show.
3. Confirm all operators know who will advance the rundown.
4. Start the show in ShoPro when the production begins.
5. Use Show Mode to advance segments, mark highlights, add live topics, and control supported graphics.
6. If you temporarily return to Edit Mode, select **Rejoin Show** to return to the active live controls.
7. End the show in ShoPro when the production is actually complete.

An accidental click in the dock can change the live rundown or graphics. Keep the dock away from display or window captures because it may contain private notes, scripts, controls, or share links.

## Protect source URLs

Treat every complete browser-source URL as private. Anyone with the full URL may be able to display that production feed. Do not publish source URLs in screenshots, stream descriptions, issue reports, or chat messages.

The `/obs` control-dock URL is not a replacement for a generated browser-source URL, and a generated source URL should not be used as the control dock.

## Troubleshooting

### The dock is missing

Open **Docks** in OBS and make sure **ShoPro Control** is checked. If necessary, reopen **Docks > Custom Browser Docks** and confirm the URL is `https://shopro.live/obs`.

### The dock asks me to sign in again

- Confirm **Remember me** was selected when signing in.
- Remember that OBS login is separate from your normal web browser.
- Check whether the OBS browser cache or profile was cleared or replaced.
- Confirm cookies are allowed for `shopro.live`.
- Sign in again; recreating the dock is normally unnecessary.

### A source is blank or stale

1. Confirm the complete source URL was copied from the correct ShoPro source.
2. Confirm the source is visible, correctly sized, and not cropped off-canvas.
3. Select **Refresh cache of current page** in the OBS browser-source properties.
4. Check that OBS can reach `shopro.live` over HTTPS.
5. Confirm firewall, VPN, DNS, and proxy settings allow secure WebSocket traffic.
6. Open the source URL in a normal browser to isolate an OBS-specific problem.
7. Recreate the source only after recording its existing dimensions and settings.

### The Test button is unavailable

Test Mode cannot be started while the real show is live. Select **Rejoin Show** to return to the live controls, or end the real show before starting a new rehearsal. If a test is already running, select **Rejoin Test**.

See [Troubleshooting](troubleshooting.md) for additional checks.
