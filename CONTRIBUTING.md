# Contributing to ShoPro Community

Thank you for helping improve ShoPro. This repository welcomes documentation corrections, workflow ideas, reproducible bug reports, and thoughtful feature requests.

The ShoPro application source is maintained privately, so this repository does not accept application-code pull requests. Documentation and community-resource pull requests are welcome.

## Before opening an issue

1. Search existing issues to avoid duplicates.
2. Check the [documentation](docs/getting-started.md) and [troubleshooting guide](docs/troubleshooting.md).
3. Remove passwords, access tokens, shared-role links, browser-source URLs, email addresses, and private production information from screenshots or logs.
4. Choose the issue form that best matches your request.

## Good bug reports

A useful report includes:

- What you were trying to accomplish
- What you expected to happen
- What actually happened
- Clear reproduction steps
- Browser and operating system
- Whether the issue occurred in planning, Test Mode, Run Mode, Studio, or an OBS browser source
- Screenshots or a short recording when they help, with private information removed

## Good feature requests

Describe the production problem before proposing a specific interface. Explain who needs the feature, when they need it, and how they handle the workflow today.

## Documentation contributions

For documentation changes:

1. Create a focused branch.
2. Keep language clear for producers and hosts who may not be developers.
3. Use relative links for files within this repository.
4. Verify commands, links, headings, and screenshots.
5. Open a pull request explaining what the change improves.

## Conduct and safety

Participation is governed by the [Code of Conduct](CODE_OF_CONDUCT.md). Report security concerns privately using [SECURITY.md](SECURITY.md), never through a public issue.
